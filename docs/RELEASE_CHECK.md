# 0.3.12 透明边缘窗口承接收起末段

- 原因：不透明主窗口的 GDI 裁切角与真实透明边缘窗口的抗锯齿合成不同，最后隐藏主窗口会替换整套边缘像素。共享画刷和圆角参数不足以消除该差异。
- 范围：只调整收起末段的绘制交接；不改时长、缓动曲线、主窗口透明属性、拖动和目录操作。
- 真实边缘窗口提前预绘，末段用主面板对应区域的实时 VisualBrush 逐渐淡出，同时真实图标逐渐显现。主窗口让出该矩形区域，终点已没有主窗口残余像素，随后隐藏主窗口不再替换轮廓。
- 上下停靠在 175% 缩放下的 1 像素居中差异统一为四舍五入。交接完成或反向展开立即释放实时画刷。
- 验证：46 项核心/集成检查通过；双屏（200%、175%）四边 48 个透明度采样通过，8 组交接前后逐字节像素差均为 0，8 组末段反向展开及引用释放检查通过。
- 61 次运动检查的尺寸、位置、拖动、菜单、反向切换等判定通过；4 项包含原生遮挡/点击判定的检查在旧版、新版中均失败，不计为完整运动回归通过。
- 验收边界：当前桌面工具无法激活临时验收窗口；旧版在相同环境下也无法通过 WindowFromPoint 遮挡/点击检查。本轮像素验证来自应用自身 WPF 渲染与原生区域查询，不等同于桌面 GPU 录屏或真人流畅度验收。保留原遮挡检查，没有放宽断言或把失败项计为通过。
- 正式包不含诊断入口、临时窗口属性、试验 alpha 代码或测试资源。

## 保留的限制

真实 Codex/交互式 PowerShell 的自动输入没有完成自动化端到端验收。Codex 识别仍依赖可访问性和界面特征；不确定的程序回退菜单。远程终端、管理员应用和自定义编辑模式不承诺自动输入。
